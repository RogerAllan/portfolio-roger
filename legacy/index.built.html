防御Segurança

Segura por padrão — na frota inteira.

Segurança não é enfeite de um projeto: é uma base que se repete em 30+ apps em produção. Explore os três anéis de defesa.

Senhas com bcrypt

Hash via passlib/bcrypt com custo ajustável — nunca texto puro, nem hash reversível.

2FA por código

Segundo fator com código comparado por hmac.compare_digest — sem brecha de timing.

JWT access + refresh

Token curto + refresh, revogável: blacklist em Redis com TTL invalida de verdade no logout.

Cookies httpOnly

Token fora do alcance do JS (Secure + SameSite) — mitiga XSS e CSRF de uma vez.

Rate limit & login guard

slowapi / express-rate-limit + lockout de tentativas contra brute-force e enumeração de conta.

RBAC como fonte única

Papéis num catálogo central; permissão verificada em toda rota — até o agente de IA age dentro dela.

Headers endurecidos

helmet em toda a frota: CSP, HSTS, X-Frame-Options: DENY, nosniff.

Timing-safe & webhooks HMAC

Comparações constantes e webhooks verificados por assinatura antes de qualquer efeito.

Sem portas abertas

Exposição só via Cloudflare Tunnel com TLS gerenciado; acesso à VPS apenas por chave SSH.

データModelagem de dados

O banco garante a regra — não só o código.

PostgreSQL modelado a sério: RBAC normalizado, integridade referencial com semântica de deleção pensada e migrations versionadas — com event tables denormalizadas onde o volume pede.

01RBAC normalizadousers ⇄ roles ⇄ permissions via tabelas de associação com PK composta.
02Integridade semânticaCASCADE nos filhos; SET NULL pra preservar auditoria e autoria.
03Invariantes no schemaUNIQUE simples e compostos — o banco garante a regra de negócio.
04Migrations versionadasAlembic e SQL incremental idempotente (IF NOT EXISTS).
05Tipos & índices certosSMALLINT/INT dimensionados, JSONB, arrays e índice em toda FK de consulta.
06Event tables p/ volumeSéries temporais denormalizadas, otimizadas pra escrita e leitura contínua.
